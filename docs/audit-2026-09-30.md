# Engineering handoff audit — 2026-09-30

Performed before any implementation, against the Linear project *Neptune — Robotics Ingestion Fabric*
(`P-MVL-11`), its design contract document, and an empty repository. Decisions marked **approved** were
confirmed by Benjamin Tay the same day and are binding until superseded by an ADR.

## 1. Understanding

**Product goal.** Neptune becomes a memory/context layer for physical AI. This project builds only the
bottom of that stack: a data compiler that turns heterogeneous robotics evidence into a canonical,
provenance-preserving, multimodal representation that later systems consume without re-parsing raw data.

**Ingestion boundary.** Input: anything a robotics team has. Output: an ingest package + receipt. The
boundary is epistemic: ingestion asserts only what exists in the evidence. Inference (failure, capability,
cause) is a later-layer derivative and must be visibly distinguishable from parsed fact.

**Canonical layer.** Modality-preserving typed records, each with provenance to an exact locator in an
immutable content-addressed source plus the transform that produced it. Missingness is a value.

**Long-term architecture.** Four input domains through one pipeline (discover → fingerprint → probe → group
→ plan → ingest → store → validate → receipt), designed for parser upgrades (new lineage), 100 GB inputs
(chunked, lazy, indexed) and hostile input (sandboxed).

## 4. Architectural challenges to the design contract

**A. Adapter ABI (approved).** Seven methods reduced to four plus a static descriptor. `resume` becomes a
runtime loop over deterministic chunk ids; `validate` splits into adapter-local findings and a cross-source
validator engine; `explain` is the structured output of `probe`/`plan` plus the descriptor. Trade-off: no
intra-chunk resume. ADR 0008.

**B. Epistemics in M1, not M8 (approved).** `Knowledge[T]` is a foundational type.

**C. No `ProvenanceEdge` entity (approved).** Embedded provenance; edges can be materialised later.

## 5. Approved decisions

- Python + uv, 3.11 floor, native-extension escape hatch reserved (ADR 0001).
- JSON Lines + canonical JSON for entities, Parquet for time-series, content-addressed blobs; no Protobuf in
  v0 (ADR 0002).
- Three identity tiers (ADR 0003). `Knowledge[T]` with field-scope rule (ADR 0004). Integer-tick timestamps
  with domains, no silent UTC (ADR 0005). Embedded provenance + `Locator` union (ADR 0006). `FrameRef` with
  no default convention (ADR 0007). Four-method adapter ABI (ADR 0008).
- Trunk-based git, protected `main`, branch per issue using Linear's name, squash-merge, conventional
  commits; Linear lifecycle Todo → In Progress → In Review → Done on merge.
- `AGENTS.md` as the single agent instruction file; `CLAUDE.md` imports it.

## 6. Highest-risk decisions, ranked

1. Clock/timestamp semantics — wrong here forces a rewrite of every adapter and all alignment.
2. Identity scheme — wrong here and nothing joins across runs, revisions, or parser versions.
3. Epistemic wrapper ergonomics — too heavy and it gets bypassed; too light and silent assumptions return.
4. Ingest package layout — every consumer depends on it.
5. Adapter ABI chunk granularity and the process boundary.
6. Python throughput ceiling on 100 GB inputs — decide native extensions explicitly by M9.
7. IR schema evolution policy.
8. Run/session grouping heuristics becoming load-bearing — keep replaceable, always manifest-overridable.

## 8. Parallel-agent plan

Single agent through M1–M2 (contracts compose; parallelising them yields incoherent types). Fan out to ~4
worktree-isolated agents at the M2→M3 transition where ~15 leaf issues unblock simultaneously. Review
bandwidth, not agent count, is the ceiling. Mechanics in `developer-workflow.md`.
